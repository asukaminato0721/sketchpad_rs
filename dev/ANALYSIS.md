# File format and runtime analysis

### Future-object display preferences

[Sketchpad 5's Color Preferences reference](https://referencecenter.dynamicgeometry.com/gsp-reference-center/windows_prefs_color.htm) defines six future-object color classes: points, lines (including segments and rays), circles (including arcs), interiors, point loci, and plots. The port now keeps the same six categories as session-local editor state and applies them centrally during document construction, including compound APIs such as function plots and loci. Existing/imported objects are not recolored, and transformed geometry continues to inherit its source style. The resulting per-object styles use the normal writer path and survive save/reopen. The checked automatic-update option makes Display > Color update each selected object's matching default class; Shift preserves the current palette. The remaining Color controls can vary newly constructed interior colors and fade timestamped trace samples over an adjustable lifetime; fading schedules redraws only while samples remain and prunes expired geometry. Background and selection colors remain independent. Exact Native trace-speed calibration and per-sketch/cross-session preference persistence remain pending.

[Sketchpad 5's Units Preferences reference](https://referencecenter.dynamicgeometry.com/gsp-reference-center/windows_prefs_units.htm) specifies separate Angle, Distance, and Other precision settings from zero through five decimal places and applies precision only to newly created values. The port now mirrors those three session defaults for new measurements and supported calculation groups, classifying area with distance and leaving existing or imported values unchanged. The existing native precision fields remain responsible for save/reopen behavior. Degree/directed-degree/radian and centimeter/inch/pixel unit selection remains pending.

[Sketchpad 5's Tools Preferences reference](https://referencecenter.dynamicgeometry.com/gsp-reference-center/windows_prefs_tools.htm) also defines the opacity of new polygons separately from per-object Opacity Properties. The port stores this as a session default over the native 16-bit opacity range and applies it only to newly created polygon interiors; existing polygons and other interior classes are unchanged. Automatic framing of new polygon perimeters and Marker/Information Tool settings remain pending.

[Sketchpad's display-attribute reference](https://referencecenter.dynamicgeometry.com/gsp-reference-center/objects_attrib_display.htm) also specifies that applied point and line styles become defaults for future similar objects. The port stores optional point-shape, line-width, and line-pattern overrides beside the color palette. Untouched function and parametric plots retain their distinct native base widths; an explicit plot override applies thereafter. Straights, rounds, point loci, and plots keep independent stroke defaults, the palette survives New/Open in the editor session, and holding Shift changes only the selected objects.

The development tools follow the same pattern as the headless probes in `../siglus_rs`: a deterministic Rust probe for file and model behavior, plus targeted analysis of the original executable. Keep conclusions tied to a fixture, a runtime observation, or a specific instruction in the original binary.

The current `gsp_probe coverage` pass decodes all 285,703 object slots in all 1,599 `.gsp` files in `../gsp-rs`, with no unsupported object kinds, parse failures, or byte-preservation failures. Editing remains guarded in 538 documents: 251 with multi-page structure, 123 with read-only image resources, and 164 with records that are preserved but not yet proven safe to rewrite. See [current decoding coverage](corpus_coverage.md) for the aggregate result and historical checkpoints. An untouched document returns its original bytes; edited documents still undergo validation and can be refused. These checks establish import and retention coverage, not complete command parity.

For native visual checks on this KDE host, `dev/native_desktop_smoke.sh` starts the winit/wgpu window and uses Spectacle to capture the actual Wayland desktop. A one-point fixture displayed its blue point, object label, menus, toolbar, and status strip without a runtime error. A polygon/perimeter fixture displayed its filled triangle, source points and labels, and the dynamic `9.53 cm` result. The isolated `dev/native_smoke.sh` path forces X11 and software GL, verifies the real window title, and captures either the built-in demo or a supplied sketch under Xvfb. For the built-in demo it also drags point A, requires the dirty-title marker, and rejects an unchanged rendered frame.

## Ghidra

The supplied `GSP5Chs.exe` is a 32-bit Windows PE with SHA-256 `5df6592cdd3475fec6c31998527f3bf78ef8bb72d476bbd1578f08d8e2c1a2c7`. `Gsp4Xrefs.java` finds the GSP4 signature; `DumpFunction.java` decompiles specified addresses. Example headless invocation after importing the executable into a Ghidra project:

```sh
XDG_CONFIG_HOME=/tmp/sketchpad-ghidra-config XDG_CACHE_HOME=/tmp/sketchpad-ghidra-cache \
  /opt/ghidra/support/analyzeHeadless /tmp/sketchpad-ghidra-project Sketchpad5 \
  -process GSP5Chs.exe -noanalysis -scriptPath "$PWD/dev/ghidra" \
  -postScript Gsp4Xrefs.java
```

The signature occurs as an immediate operand at `00416296` (`CMP ECX,0x34505347`), `00416642`, and `004f5b52`. The first is in a reader function entered at `00416230`; the second is in a header writer entered at `00416610`. The page writer at `004a8520` counts objects in its linked list before calling `004a80f0`, which emits the `1000` page preamble record. This supports the observed fixture behavior: a one-object file has value `1` at offset `+24` of the `0x3e8` preamble payload, and updating that value to `9` was required before the generated nine-object file opened in Sketchpad 5. The exact semantics of the other preamble fields remain unverified.

A second check reopened that original-app save in Rust, moved point 2, saved a new file, and opened the new file in Sketchpad 5. The nine-object sketch rendered there. This confirms a limited bidirectional edit/save/open cycle for these object kinds.

`tests/replay_intersection.txt` constructs two segments and their crossing, then saves it. Sketchpad 5 opened the Rust-generated file and rendered the crossing point. The source fixture uses object code `9` with references to the two straight objects; the port uses that record layout for writing.

### Round-arc intersections

Native-created ordinary line-circle and circle-circle controls confirm that the construction command emits code `11` before `12` and code `13` before `14`. This matches the editor's branch creation order and ensures a tangent or clipped single hit retains the first Native branch.

Native-created circle-arc and arc-arc controls use code `13` for the first crossing along the second arc and code `14` for the second; when the arc is the first operand, traversal is reversed. Reversing circle-arc selection confirmed the ordered-parent rule. Hiding the upper crossing in Native independently identified the corresponding serialized branch in all three two-hit controls. A quarter-arc control with one surviving crossing created only code `13`; a separately authored code-`14` control still displayed that sole hit and saved unchanged, so file evaluation preserves Native's shared single-hit behavior while the editor avoids creating duplicates.

Port-authored two-hit circle-arc and arc-arc files rendered both crossings in Sketchpad 5 and saved byte-identically at 2,368 and 2,440 bytes, with SHA-256 values `64e2329de7cf0e45b9f09de4fecea169e134630b4e8e252869f31c5b3df498a7` and `51bc65d10a7fa92a489ff5b01576b533381c1b93ee233605794249c46153c9e4`. The editor now emits code `13` before code `14`, skips undefined branches, and coalesces tangent or arc-clipped duplicates just as the Native construction command does.

Multi-page encoding uses the same analytic identities and page-local parent references. One port-authored 20-object, two-page document combined both branches of straight-arc, circle-arc, and arc-arc intersections. Native displayed the page-2 geometry and saved the 4,368-byte file unchanged (`2f3db01c15eccfc1a34012139dac48704eaf615db74d942526b008d82e9a922f`).

### Polygon-boundary intersections

Native code `93` retains the ordered straight and polygon parents and chooses the nearest polygon-boundary event strictly ahead of the straight origin. Segment, ray, and line identities use the same directed carrier behavior; collinear spans contribute endpoint events. The evaluator preserves undefined live results, and the writer rejects invalid or cross-page parent roles.

A port-authored ten-object, two-page document placed a four-vertex polygon, line, and boundary intersection on page 2. The port reopened the result at `(250, 200)`, and Sketchpad 5 displayed and saved all 3,716 bytes unchanged. Its SHA-256 is `6dfc78bf30c0840a8aab00a1612c225518f520c31eaf1a0401a2c70c447e4777`.
