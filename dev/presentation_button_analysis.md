# Presentation Action Button

The [Sketchpad 5 Reference Center](https://referencecenter.dynamicgeometry.com/gsp-reference-center/objects_btns_presentprops.htm) describes Presentation as an action button that activates selected action buttons simultaneously or sequentially. Sequential mode waits for an action to finish before continuing, and a further click can advance it.

## Native records

`action_presentation_default_original.gsp` has two Hide/Show parents and a native default simultaneous Presentation. `action_presentation_sequential_scroll_original.gsp` has two Scroll parents and a native sequential Presentation. The object code is 62. Its six records are `0x07d0`, `0x07d2`, `0x0906`, `0x07d5`, `0x07d8`, and `0x07d7`. The reference record stores a count followed by the selected action button IDs in order. The `0x0906` payload has action code 7 at offset 12, option flags at offset 14, a duration/pause word at offset 16, a separate native state word at offset 18, and the button anchor at offsets 20–23. The native labels in these fixtures are `系列2个操作` and `顺序2个操作`. `assets/action_presentation_group.bin` preserves the default 156-byte group.

Disposable native-property probes establish the option fields. Flag bit 0 selects sequential mode. Bits 1, 2, and 3 select Deselect Objects, Stop Animations, and Erase Traces before starting. In simultaneous mode bits 4–5 encode stop after last action (`0x00`), first action (`0x10`), or elapsed time (`0x20`); `0x30` is not admitted. Sequential mode leaves these stop bits clear. Offset 16 stores tenths of a second: native saves 2.5 seconds as 25 for both elapsed-time stopping and pause-between-actions. Native defaults are 600 (60 seconds) for simultaneous and zero for sequential. Offset 18 varies independently from the duration and is bounded by the target count in the corpus. Its behavioral meaning is not proved, so the importer preserves it as `native_state` and newly authored buttons write zero.

The native original and clicked fixtures import as editable with `partial_view=false` and preserve their bytes on unedited save. Reopening the native-created default and saving without a click produced `action_presentation_default_opened_by_wine.gsp`, where both points are hidden and both parents have Show actions. Clicking its Presentation and saving produced `action_presentation_default_clicked.gsp`, where both points are visible again.

## Port behavior and cross-open checks

`PresentationButtonGroup` reads and writes the observed group while retaining unknown record bytes. The document model validates selected parent action buttons, keeps their order, and preserves all proved settings. The editor dialog exposes simultaneous/sequential mode, the three Before Starting controls, the simultaneous stop condition, elapsed seconds, and sequential pause seconds. Runtime applies the cleanup controls, stops simultaneous children after the last action, first action, or timer, and pauses between sequential actions. A second click advances a sequential presentation or stops simultaneous running actions. Hide/Show, Animation, Movement, Scroll, Link, and nested Presentation parents use the shared action dispatch; only running motion contributes to completion tracking.

`tests/replay_presentation_button.txt` generates simultaneous and sequential files from two Hide/Show parents. Both opened and saved byte-identically in native Sketchpad 5. Clicking either port-generated Presentation there hid both points and changed both parents to Show. `action_presentation_port_simultaneous_clicked_by_wine.gsp` and `action_presentation_port_sequential_clicked_by_wine.gsp` preserve these results. A click in the Rust desktop editor produced the same object state in `action_presentation_port_desktop_clicked.gsp`; that saved file then opened and saved byte-identically in native Sketchpad 5. The advanced-setting probes were made on disposable copies and establish the wire mutation, while the Rust regression assertions cover their runtime behavior.

`tests/replay_multi_page_presentation.txt` adds a simultaneous Presentation button on page 2 of a two-page document with two Hide/Show buttons. The port stores their page-local ordinals `[5, 6]` after the reference count, corresponding to global object IDs `[6, 7]`. The generated file opened and saved byte-identically in native Sketchpad 5. Clicking the Presentation button there hid all three parent targets, changed both Hide/Show actions to Show, and kept page 1 visible. The native-clicked file imports and round-trips in Rust.

`tests/replay_multi_page_presentation_sequential.txt` creates the same page-2 button in sequential mode. After the Wine harness waited for Sketchpad's startup and file-open window, the generated file opened and saved byte-identically. A native click hid the same three parent targets. Both clicked modes retain their mode values and import byte-identically in Rust.

## Corpus result

The settings admission restores 135 drawing code-62 Presentation buttons, 29 dependent drawing objects, and four embedded-prototype Presentation buttons: 168 slots total. Unsupported slots fall 4,479→4,311, all-kind-complete documents rise 1,089→1,108, and drawing-complete documents rise 1,114→1,134. All 1,599 originals remain byte-exact. The remaining 64 drawing code-62 objects contain Animation, Movement, Scroll, or action-code-8 variants; no corpus-observed Presentation action remains rejected.
