# Graph > Plot Table Data

The [Sketchpad reference](https://referencecenter.dynamicgeometry.com/gsp-reference-center/menus_graph_plottabledata.htm) says the command plots one point per table row and lets the user choose the two columns and Cartesian or polar coordinates. The current probe covers one row in a two-column table of default parameters.

The original app created `table_two_parameters_original.gsp` with `t[1]` and `t[2]`, then `table_two_columns_original.gsp` by selecting both and choosing Number > Tabulate. The table is code 91. Its `0x07d2` payload is `[2, 2, 1]`: two column references in display order `t[2], t[1]`. The `0x090d` payload is 100 bytes for one row. `plot_table_data_base_original.gsp` adds the default coordinate frame. Selecting the table and choosing Graph > Plot Table Data opens a coordinate dialog with `(t[2], t[1])` and Cartesian selected. Confirming it produced `plot_table_data_original.gsp`.

The plotted object is code 67 with `0x07d0`, `0x07d2`, `0x07d3`, and `0x07d7`, matching the existing Plot Points record layout. Its references are `[1, 9]` (the first parameter and the frame), and the stored Cartesian coordinates are `(1, 1)`. The point appears at the frame's `(1, 1)` position. The table's `0x090d` record also gained two nonzero bytes in a trailing padding region; the parser preserves that observed variant.

The original app's Add Table Data command produced a second row with the same `(1, 1)` values in `table_two_columns_two_rows_original.gsp`. Plot Table Data produced the same single code 67 group as the one-row case; these duplicate positions appear to be combined. The table's `0x090d` payload grew from 100 to 124 bytes. `plot_table_data_two_rows_original.gsp` preserves the plotted result.

Editing `t[2]` to 2.00 after adding the second row produced `(1, 1)` and `(2, 1)` in `table_two_columns_distinct_rows_original.gsp`. The parameter's `0x0907` payload changed its final value word from 1 to 2; the table changed the first digit of the live row's cached x value. Plot Table Data created two code 67 points, with stored coordinates `(1, 1)` and `(2, 1)`, in `plot_table_distinct_original.gsp`. Their record references are both `[1, 9]`. This verifies that each distinct table row is represented by its stored Cartesian coordinates.

Editing t₂ to 2.50 in a one-row table yielded `table_pair_fraction_original.gsp`; its cached text changed from `1.00` to `2.50` without changing the table group length. Plot Table Data stored `(2.5, 1)` in a code 67 point. The generated point group matches `plot_table_fraction_original.gsp` byte for byte. Editing t₂ again to 3.25 updated the table row but left the plotted point at `(2.5, 1)`, as captured in `plot_table_fraction_after_value_change_original.gsp`.

Choosing polar coordinates for the original one-row `(2.5, 1)` table produced `plot_table_fraction_polar_original.gsp`: a code 68 point with stored radius `2.5` and angle `0.017453292519943334` radians. Its generated point group matches byte-for-byte. The original distinct two-row table produced two polar points with radii `1` and `2` at the same one-degree angle in `plot_table_distinct_polar_original.gsp`. The port reproduces their decoded values and positions. Sketchpad 5 opened and saved the generated one- and two-point polar files byte-identically. The original second point group contains different opaque header bytes, and the original selects both new points; the generated file uses the existing point template and selects the last point.

The port now reads and writes t₁/t₂ values with two decimal places, their one- to 256-row table when both table values are −99.99 to 99.99, and one point per distinct Cartesian or polar row. `tests/table_pair_five_distinct_polar_replay.txt` creates five distinct cached t₂ values, plots five polar points, and produces a file that Sketchpad 5 opened and saved byte-identically. Rust tests check exact original bytes, generated bytes, table movement, frame movement, and fixed point positions after parameter edits. Other table sources and column choices remain to be probed and implemented.

The same table can be plotted again after its live parameter changes. `tests/table_pair_replot_polar_replay.txt` changes t₂ from 5.75 to 6.00 and adds five new polar point objects while retaining the five earlier points. Sketchpad 5 opened and saved the generated 19-object file byte-identically.

`tests/table_pair_late_sources_polar_replay.txt` places a free point before the parameters and table. The table references parameter IDs `[3, 2]`, and the polar points reference the first page object and coordinate frame `[1, 10]`. Sketchpad 5 opened and saved this generated file byte-identically.

`tests/table_pair_both_columns_cartesian_replay.txt` changes both parameters before and after tabulation. The cached rows are `(3.25, 2.50)` and `(5.75, 4.00)`, and the two plotted Cartesian points keep those values after later parameter edits. Sketchpad 5 displayed both table columns and saved the generated file byte-identically.

`tests/table_pair_mixed_width_plot_replay.txt` uses cached rows `(−2.50, 12.34)`, `(12.34, −3.25)`, and `(3.25, 2.50)`. The native application displayed all three rows and saved the generated Cartesian plot file byte-identically. Its negative and two-digit source fixtures also decode and preserve their bytes.
