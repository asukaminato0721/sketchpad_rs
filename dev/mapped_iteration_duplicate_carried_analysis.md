# Duplicate carried references in mapped iterations

The post-Plot-Value frontier contained 62 ready code-89 roots. A temporary trace
of the current production predicate separated 64 rejected mapping attempts in
their 42 files: 23 broader loci, 18 unsupported carried-object roles, 18
duplicate carried tails, two duplicate-seed mappings, two branch type mismatches,
and one unsupported seed. The trace was removed after the audit.

The duplicate-carried cases do not represent multiplicity. Native stores an
ordered dependency packet after the depth source, seeds, and branch images, and
some documents repeat a prerequisite or branch image in that packet. Evaluation
already traverses this packet as a visited construction DAG. Import therefore
keeps the first occurrence of each carried ID before applying the unchanged
validator. The original records remain authoritative for unchanged saves, so
their duplicate wire references are preserved. Fresh public construction keeps
the unique-carried-input requirement and cannot generate redundant packets.
