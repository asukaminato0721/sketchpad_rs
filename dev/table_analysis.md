# Number, calculation, and table records

## Scope and source

These layouts came from Sketchpad 5 run under Wine with a shared-prefix lock. `dev/table_wine_probe.sh` creates original application fixtures; `dev/table_record_probe.rs` writes bounded variants from Rust. The original files are in `tests/fixtures/table_*`. No layout was inferred solely from the sibling project. Its decimal-tail decoder in `../gsp-rs/src/runtime/extract/decode.rs` was used as a second check.

The port writes default `t[1]` and `t[2]` parameters and multiple named ASCII parameters in supported single-page sketches, with editable values from −99.99 to 99.99 at up to two-decimal precision. Named parameters increase their display precision when a value needs a second decimal place. It also writes the literal `2 + 3 = 5.00` calculation, the one-column t₁ table with values from −99.99 to 99.99, named parameter tables with snapshot rows, and a two-column t₂/t₁ table with one to 256 rows. Both two-column values also range from −99.99 to 99.99. Unicode names, values beyond these ranges, formulas, and other column combinations remain unsupported for structural edits. The strict parsers leave other records in partial view and refuse saves that could lose content.

## Record groups

| Object | Header code | Record sequence | Verified fields |
| --- | ---: | --- | --- |
| Default parameter | 0 | `07d0 0907 07d5 07d8 08a3 07d7` | `0907` anchor at payload bytes 12–15; `07d5` label `t[1]`; `08a3` rectangle `(x,y,x+94,y+32)` |
| Literal calculation | 0 | `07d0 0907 07d8 08a3 07d7` | `0907` anchor at bytes 12–15; `08a3` rectangle `(x,y,x+114,y+26)` |
| One-column table | 91 | `07d0 07d2 090d 07d8 07d7` | `07d2` references its parameter ID; `090d` anchor at bytes 12–15 and row count plus two at byte 16 |

The original `090d` table layout begins with its own `090d` tag and a 32-bit inner length at byte 4. With four-character values, a one-row table has 64 payload bytes and two rows have 80 bytes. Each cached row adds `0<H<TNxVALUE>>`, where `N` is the UTF-8 byte length of the displayed value, followed by alignment padding. The first row's fixed header is retained from the original fixture. `src/table_records.rs` checks the full canonical layout and caps rows at 256. Editing the original tabulated t₁ from 1.00 to 2.50 changed only its cached row text to `0<H<T4x2.50>>` while preserving the 64-byte payload. `table_t1_tabulated_edited_original.gsp` now decodes without partial view and roundtrips byte-identically. `table_t1_snapshots_generated.gsp` caches `2.50` and `3.25`; Sketchpad 5 displayed both rows and saved it unchanged.

Original negative and two-digit edits produced `0<H<T7x–2.50>>` and `0<H<T5x12.34>>`, respectively, with 68-byte `090d` payloads after alignment. The negative sign is an en dash encoded as three UTF-8 bytes. `table_t1_tabulated_negative_original.gsp` and `table_t1_tabulated_two_digit_original.gsp` now parse without partial view and preserve their bytes. `table_t1_mixed_width_snapshots_generated.gsp` combines cached values `−2.50`, `12.34`, and `−99.99`; Sketchpad 5 displayed all three rows and saved the generated file byte-identically.

`table_t1_late_source_snapshots_generated.gsp` puts a free point before the t₁ parameter, so the one-column table references object 2 and occupies object 3. It caches `2.50` and `3.25`, parses without partial view, and Sketchpad 5 displayed both rows and saved the file byte-identically.

The default parameter's `0907` payload ends with two-byte decimal words. Single-digit values use one word; `3.25` uses `[3, 10, 2, 5]`, where 10 marks the decimal point; `−2.5` uses `[4097, 2, 10, 5]`, where 4097 marks the sign. `12.34` uses `[1, 2, 10, 3, 4]`. The inner length and digit count grow with these words. The port writes values within ±99.99 with up to two decimal places, adjusts the parameter box for an extra sign or integer digit, and retains source-file opaque bytes. Original fixtures for fractional, negative, and two-digit values parse without partial view; generated examples opened and saved byte-identically in Sketchpad 5.

The original `speed = 2.5`, `speed = 3.25`, and `test = 2.5` fixtures show that a named parameter uses a type-7 `07d5` label: 22 fixed bytes, a two-byte ASCII name length, name bytes, a null terminator, and zero padding to an even record length. Its `0907` precision is 1 with a 0.1 step for `2.5`; two decimals use precision 2 and a 0.01 step. The parameter box grows by 10 units for that extra decimal. Generated `speed` files with both precisions and an even-length `test` name opened and saved byte-identically in Sketchpad 5. A renamed default `t[1]` with label `a` uses the default parameter's numeric header instead and also parses without partial view.

A one-row table for `speed = 2.5` has a 60-byte `090d` layout. The text after its 28-byte header is `000<SS2<T5xspeed>>0<H<T3x2.5>>` plus zero padding to a four-byte boundary. The `07d2` record carries the source object ID; the original `test = 0.25` table points to object 5. The original app's Add Table Data command appends another `0<H<T3x2.5>>`, increases the `090d` length by 12, and increments the stored row count. The final row displays the live parameter value even when its cached text differs. When adding a row, Sketchpad replaces that last cache with the live value before appending the next live row. The original `2.5` cache with a live `3.25` parameter thus became two `3.25` rows after Add Table Data. Rust reconstructs these original groups byte for byte and preserves the original full files; its generated two- and three-row files cross-opened in Sketchpad 5.

The two-row table in `plot_points_table_two_rows_original.gsp` differs from the canonical table only at the penultimate `090d` padding byte, which contains `t` instead of zero. The parser accepts this exact observed variant and retains its original bytes on save.

The original third-row pair table is `table_pair_three_rows_distinct_original.gsp`. Its `090d` payload grows from 124 to 148 bytes and its cached t₂ row values begin at group offsets 143, 168, and 193. The third-row save required a table drag to persist, as in earlier row probes. The parser preserves the original group. A generated three-row table with three distinct t₂ values and polar plotted points opened and saved byte-identically in Sketchpad 5.

The original app also added a fourth row when opening the port-generated three-row table. `table_pair_four_rows_original.gsp` preserves that result. Its `090d` payload is 172 bytes, and t₂ row values begin at group offsets 143, 168, 193, and 218. The parser now accepts this original file. The writer uses the original 72-byte layout prefix followed by tagged value cells and four-byte alignment. For four-character values, each row is 25 bytes: the payload length is `align_up(72 + 25n, 4)`, and cached t₂ and t₁ values start at group offsets `143 + 25i` and `155 + 25i` for zero-based row `i`. Wider values grow the row according to their UTF-8 byte length. The port bounds this layout at 256 rows. `table_pair_five_distinct_polar_generated.gsp` contains five distinct cached rows and five plotted points; Sketchpad 5 opened and saved it byte-identically.

Native edits produced `table_pair_negative_x_original.gsp` with `0<H<T7x–2.50>><H<T4x1.00>>` and `table_pair_two_digit_y_original.gsp` with `0<H<T4x1.00>><H<T5x12.34>>`. Both now parse without partial view and preserve their bytes, including the native two-digit file's nonzero alignment byte. `table_pair_mixed_width_plot_generated.gsp` combines three rows with negative and two-digit values in both columns and three stored Cartesian points. Sketchpad 5 displayed the table and saved the file byte-identically.

Removing a row from that five-row file produces `table_pair_four_rows_after_remove_generated.gsp`. The earlier cached t₂ values remain `1.00`, `2.00`, and `3.25`, while the live final row remains `5.75`; all five previously plotted points stay fixed. Sketchpad 5 opened and saved the generated four-row file byte-identically. Rust tests also cover successive removals and the one-row lower bound.

The pair table's `07d2` source IDs can be moved beyond objects 1 and 2. `table_pair_late_sources_polar_generated.gsp` begins with a free point, puts t₁ and t₂ at IDs 2 and 3, and writes table source IDs `[3, 2]` at object 4. It initializes the first row from an already edited t₂ value of `2.00`, adds a second row with `3.25`, and plots in a frame at object 10. Sketchpad 5 opened and saved the generated file byte-identically.

`table_pair_both_columns_cartesian_generated.gsp` starts with t₁ = 2.50 and t₂ = 3.25, then caches a second row after edits to t₁ = 4.00 and t₂ = 5.75. The table's two columns read `(3.25, 2.50)` and `(5.75, 4.00)` in Sketchpad 5. Both Cartesian point records use these stored pairs, and Sketchpad 5 saved the generated file byte-identically. Later edits to either live parameter update only the final cached row; prior plotted points stay fixed.

The original application changes opaque bytes 22–23 and 30–31 of the parameter `0907` payload during some saves; these bytes are carried through unchanged. Dragging the parameter shifts its `0907` anchor and all four `08a3` coordinates by the same delta. Dragging a table changes only its `090d` anchor. The Rust writers reject coordinate overflow before mutation.

The original UI's Add Table Data and Remove Table Data operations visibly changed rows but Ctrl+S alone did not update the file in these probes. Dragging the table then saving persisted the changed row count. The fixtures `table_parameter_two_rows.gsp` and `table_parameter_row_removed.gsp` capture the persisted layouts. The port marks each row edit dirty immediately.

## Verification

- `rustc --edition=2024 --test src/table_records.rs -o /tmp/sketchpad_table_records_tests && /tmp/sketchpad_table_records_tests` checks bounded encoding, original drag positions, row addition, and rejection of unsupported parameter values.
- `cargo test -q` passed 123 tests after integration. `cargo run --quiet --bin gsp_probe -- replay tests/replay_table.txt` and `... tests/replay_calculation.txt` passed save/reopen checks.
- Rust-generated standalone parameter, calculation, and table files opened visibly in the original Sketchpad 5 and saved. The integrated replay files also opened and saved there. Captures: `/tmp/sketchpad_number_integrated_before_save.png` and `/tmp/sketchpad_calculation_integrated_before_save.png`. Their original-saved copies are `table_integrated_saved_by_wine.gsp` and `table_calculation_integrated_saved_by_wine.gsp`.
- `gsp_probe verify` reopened those original-saved integrated files as two and one objects respectively, both with `partial=false`. The original application's row-removed fixture also reopened with `partial=false` after accepting its observed opaque padding changes.

The native UI draws and hit-tests the bounded number objects using page anchors, and the SVG path renders the same text and rows. Original-app cross-open is the compatibility proof for generated GSP files; native canvas interaction was checked through code and replay, not by an automated GUI assertion.
