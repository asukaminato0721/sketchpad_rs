# Numeric-ratio dilation

Native Sketchpad Mark Ratio accepts a selected scalar numeric value, in addition to three collinear points. A selected parameter n=0.5 produces a default marked-value dilation dialog. Native point, segment, circle, and polygon operations use code 33, references `[source, center, numeric ratio]`, and no constraint payload. The four complete 68-byte native object groups equal the port-generated groups. Code 31 is not used by this verified workflow; the sibling decoder names code 33 as an expression rotation, which disagrees with these native records.

The typed `CalculatedRatioScaled*` variants import, evaluate, create, remap dependencies, and save this format. Parameters and any supported finite scalar-valued measurements/calculations can supply the ratio; dimensional values are rejected. Geometry uses the same scale about a center as fixed dilation. Circle radii use the absolute factor; zero radii are not displayed, but their native object records remain editable and saveable. The point variant participates in the shared iteration evaluator. See `dev/iteration_analysis.md` for iteration evidence.

`tests/replay_numeric_ratio_dilation.txt` recreates the four baselines and thirteen generated originals/edits. Native creation results are `tests/fixtures/numeric_ratio_{point,segment,circle,polygon}_native.gsp`. To reproduce creation, use the corresponding `numeric_ratio_*_base_port.gsp` with `dev/wine_roundtrip.sh` and set `SKETCHPAD_WINE_SETUP_SCRIPT` to `dev/numeric_ratio_dilation_wine_setup.sh`. Set `SKETCHPAD_RATIO_SHAPE_X/Y` to point 279/249, segment 279/269, circle 319/249, or polygon 299/279. The script marks the center and parameter, then invokes Dilate. Regression tests preserve the native files and compare complete object groups against generated output.
