# Measurement decimal precision

The standard measurement format is a 32-byte `0903` payload. Its u16 field at offset 28 controls decimal places. It uses the same position in code 36 length, 37 distance, 39 perimeter, 40 circumference, 41 angle, 42 circle/polygon area, 43 arc angle, 44 arc length, 46 radius, and 47 point ratio groups. Existing position, style, and other presentation bytes remain intact.

A native record probe displayed a length with zero decimals, circle area with three, and an angle with four, preserving its bytes on save. A raw value of ten did not display ten decimal places; it displayed a five-decimal radius. That additional format value remains unimplemented. The supported editor and importer explicitly cover decimal precision 0–5, including verified five-decimal radius/distance captions.

`tests/replay_measurement_precision.txt` generates basic original/edited examples, polygon/perimeter/circumference/ratio/distance examples, arc examples, and a two-page original/edit. The basic file displays length=1 cm, area=5.498 cm², radius=1.32292 cm, and angle=45.0000°. Its doubled-length formula still displays 2.65 cm, proving that display precision does not round the calculation input. Moving the endpoint changes those results while retaining each measurement’s saved precision. Arc captions show 180.0° and 2.494 cm. All six generated files open and save byte-identically in native Sketchpad. To inspect the edited second page, a separate copy changed only the initial page index in `0384` to 1; native Sketchpad displayed 1.323 cm and saved that copy byte-identically.

The object stores optional measurement precision, initialized to two for new standard measurements and decoded from native records. Clipboard entries now have named fields and preserve this value. Undo snapshots retain it with the object. The final record pass patches the precision field after normal group encoding, using page order and surviving objects so it also covers added pages, copied objects, and deletion. Supported multi-page source edits permit this field change; page-local references remain unchanged.

Desktop overlay captions and SVG share `Document::measurement_text`, which uses the native-verified numeric display rounding helper. Source numeric values and dependent formulas retain full precision. Regression tests cover all eleven native group kinds, byte preservation, source values, undo/redo, invalid mixed selections and precision bounds, copy/paste, deletion, page ordering when construction starts on the second page, editing an existing page, and consistent desktop/SVG text.

The page-2 inspection identified a separate active-page save gap. It is now fixed and verified as described in `dev/multi_page_edit_analysis.md`.

## Scalar coordinate and constrained-point measurements

The same `0903` precision field is verified for code 65 abscissa, 66 ordinate, 86 coordinate distance, 87 slope, and 94 Value of Point. Their strict record readers now accept precision 0–5 while retaining the other layout checks. The document captures the field for imported objects, initializes it for new ones, and uses the existing clipboard, undo, save, and selection paths. Coordinate pairs and line/circle equations use rich-text readout formats and remain outside this decimal-field implementation.

`tests/replay_scalar_measurement_precision.txt` writes coordinate originals/edits and Value of Point originals/edits with a calculated iteration depth. The coordinate source displayed as x=1 still doubles to 2.70, confirming use of its full value. The constrained point changes from 0.25 to 0.675 while its saved precision changes from five to zero decimals. Native Sketchpad displays the point value as 1, its multiplied result as 2.70, its rounded depth as 3.00, and three repeated images. All four files save byte-identically in native Sketchpad; the independent coordinate precision probe is preserved as `scalar_precision_coordinates_native_verified.gsp`.

Regressions cover all five added measurement kinds, native imports and byte preservation, source evaluation, precision edits/undo, clipboard dependencies and precision, a slope becoming undefined, Value of Point controlling calculated iteration depth, and decimal digits in desktop/SVG captions. Scalar captions share `Document::measurement_value_text`; equations and coordinate pairs retain their existing formatting.

## Calculation caption precision

All four supported calculation layouts store decimal precision at offset 28 in their `0907` payload: source-free code 0, measured-length code 48, two-length code 48, and generic source-dependent code 48. Parsing now validates precision 0–5 and preserves it. Setters change only those two bytes and reparse before committing. Literal calculations, measured arithmetic, and two-length arithmetic now render using their saved precision; generic formulas already did. Attached point numeric labels use the corresponding calculation formatter.

`calculation_precision_native_verified.gsp` verifies native captions 5.292 cm (three places), 2.0000 (four), 0.24690 (five), and 5 (zero, underlying result 5.125). Native open/save is byte-identical. `tests/replay_calculation_precision.txt` creates the mixed layouts and edits precision, parameter inputs, and geometry. The mixed `Document::set_numeric_precision` operation validates the entire selection before one checkpoint; existing measurement-only precision calls remain available. Calculation precision edits currently require a supported single-page sketch.

The probe exposed numeric-group visibility bytes being compared against unmodified kind records during save validation. The validator now derives expected visibility from the object while preserving and comparing every other record byte. Added numeric groups explicitly set or clear the visibility bit, covering copied hidden parameters that are shown before saving. Regression coverage includes hide/show for every supported calculation layout, parameters, both table layouts, and copied parameters.

## Scientific numeric captions

Native probes verify a shared formatting rule: magnitudes strictly greater than 10⁶ use a decimal mantissa and a superscript exponent, while exactly ±10⁶ stays in fixed notation. Small magnitudes retain fixed notation (0.000001 displays 0.00 at two decimals). Exponent rounding is normalized: 9999999 displays 1.00 · 10⁷. The shared numeric formatter applies these rules to parameters, supported scalar measurements, and all four calculation layouts, while preserving saved precision, units, and full numeric inputs.

`tests/replay_scientific_captions.txt` reproduces native-verified source-free scalar/degree formulas, threshold parameters, negative values, exponent rounding, tan(90°), chained measured-length arithmetic, a length product, a generic length formula, and circle area. Their native saves are byte-identical; captions show 2.57 · 10⁶ cm, 6.72 · 10⁸ cm², 2.65 · 10⁶ cm, and area 1.37 · 10⁶ cm². The edited dimensional example moves an endpoint and sets four display decimals. Tests also cover numeric labels, unchanged full values, copied dependencies, reopened precision, and SVG captions. Coordinate pairs and equation rich-text formatting retain their separate implementation.
