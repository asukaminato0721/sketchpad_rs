# Points constrained to rays and lines

Native Sketchpad 5 saves points on a line and ray as object code 15 with one page-local host reference. Their `0x07d3` constraint records have a 12-byte payload: `15, 12, t` for a line and `15, 13, t` for a ray, where `t` is a little-endian `f64` after the two `u16` codes. The existing segment constraint uses subtype 14. Native files in `tests/fixtures/point_on_line_native.gsp` and `point_on_ray_native.gsp` both store `t = 0.3` and now import as editable objects with `partial_view=false`.

The Rust writer emits object groups byte-identical to the native examples at the same parameter. A ray parameter may exceed one; a line parameter may be negative. New and moved points on both hosts, including those outside the interval between the host's defining points, opened and saved byte-identically in native Sketchpad 5. Page 2 line and ray points also opened and saved byte-identically; native screenshots show the line point before its first defining point and the ray point beyond its second defining point. `tests/replay_straight_path_points.txt` reproduces six generated point files and a copy/paste result on an earlier page. The page 2 files and earlier-page paste opened and saved byte-identically in native Sketchpad 5; representative new and moved single-page files did too. The Point tool and Construct > Point on Object can create these constraints. The replay `check` command now uses the same page-order-aware round-trip validation as Save, so it verifies the earlier-page paste correctly.
