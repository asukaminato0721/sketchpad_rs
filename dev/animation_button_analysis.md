# Animation Action Button

`tests/replay_animation_button_base.txt` creates a segment and a point at its midpoint. In Sketchpad 5, selecting the point and choosing Edit > Action Buttons > Animation opens a settings dialog. Accepting its defaults creates a code-62 button labeled `动画点` (Animate Point). The native file is `tests/fixtures/action_animation_original.gsp`.

The button group has seven records: `0x07d0` (28-byte header), `0x07d2` (one target, point 4), `0x07d3` (36-byte animation settings), `0x0906` (24-byte action payload), `0x07d5` (label), `0x07d8` (auxiliary), and `0x07d7` (terminator). The action payload has nested code `0x0906`, length 24, code 12 at offset 8, value 2 at offset 12, and the button's screen anchor at offsets 20–23. `assets/action_animation_group.bin` preserves the native 188-byte group. The settings payload remains opaque so its unrecognized fields survive file edits.

Clicking the native button moved the constrained point from parameter 0.5 to 0.60276 in the saved sample while leaving the button group unchanged. The clicked file is `tests/fixtures/action_animation_clicked.gsp`. The native button did not show a floating Motion Controller in the click capture.

The port decodes this default group as an editable Animation Button. Edit > Action Buttons > Animation creates one for a free point or a point on a segment, ray, line, circle, or arc. A click starts that point in the existing motion engine without opening the controller. The native and clicked files import with `partial_view=false` and reencode byte-identically. `tests/replay_animation_button.txt` creates an English `Animate Point` button. Sketchpad 5 opened and saved that port-generated file byte-identically (2,240 bytes, 91 records). Clicking it moved the point; the resulting native save is `tests/fixtures/action_animation_port_clicked_by_wine.gsp` and reencodes byte-identically in the port. Desktop captures at `/tmp/sketchpad_animation_button_port_before.png` and `/tmp/sketchpad_animation_button_port_after_one.png` show the port button and the point's motion.

## Direction, speed, and travel

For a point on a segment, changing the native Direction menu altered only byte 7 of the `0x07d3` settings payload: `0x00` forward, `0x10` backward, `0x20` bidirectional (default), and `0x30` random. Checking Once Only after choosing forward changed that byte to `0x80`. The native speed presets changed only the 32-bit float at payload offset 8: slow `4.0`, medium `24.0` (default), and fast `80.0`. Native examples are `action_animation_{forward,backward,random,slow,fast,forward_once}_original.gsp`; all import and round-trip exactly.

The port's button dialog now offers those directions, Once Only when applicable, the three speed presets, and a custom numeric speed. A button click applies the chosen settings to its point's motion. Forward and backward wrap around a path; bidirectional motion reverses at an open path's endpoints; random motion samples a new path position. Once Only stops after a random move or a full trip back to the starting position. A second click stops a running button. This follows the [Sketchpad 5 Reference Center's Animation Button behavior](https://referencecenter.dynamicgeometry.com/gsp-reference-center/objects_btns_animateprops.htm). `tests/replay_animation_button_variants.txt` generated a forward/fast/Once Only button and a backward/slow button; Sketchpad 5 opened and saved the combined file byte-identically (2,432 bytes). It also accepted a port-generated custom speed of `12.5` byte-identically.

Native buttons for a circle point and a free point use direction code `0x00` at medium speed. The free-point dialog hides the direction menu; free points wander at random regardless of the stored code. The port creates those native defaults for each point type. `action_animation_circle_original.gsp` and `action_animation_free_original.gsp` import and round-trip exactly, and port-generated circle and free-point button files opened and saved byte-identically in Sketchpad 5.

The desktop Edit > Action Buttons > Animation flow was also exercised under Xvfb. Choosing Create added the fifth object, File > Save wrote a 2,240-byte sketch, and Sketchpad 5 opened and resaved that exact file byte-identically.

## Two-point buttons

The native `action_animation_two_points_original.gsp` stores target IDs `4` and `5` in its `0x07d2` record. Its `0x07d3` settings payload is 68 bytes: a four-byte prefix followed by one 32-byte settings block per point. Selecting the second point in the native dialog and changing its direction to Backward changed only byte 39 of that payload, leaving the first point bidirectional. `action_animation_two_points_second_backward.gsp` captures this setting. Clicking the native default button moved both points; `action_animation_two_points_clicked.gsp` preserves the result.

The port imports all three native files without partial view and round-trips them byte-identically. Its dialog lists the selected points and edits each point's settings separately. The desktop default and second-point-Backward saves matched `tests/replay_animation_button_two_points.txt` byte-for-byte. Both replay files opened and saved byte-identically in Sketchpad 5; clicking the port-generated default there moved both points, and `action_animation_two_points_port_clicked_by_wine.gsp` imports without partial view. In the port, one click starts both tracks and a second click stops both.

## Three-point and mixed buttons

Sketchpad 5 created `action_animation_three_points_native.gsp` from three selected points on one segment. The target record contains IDs 4, 5, and 6, and the settings record has 100 bytes: a four-byte prefix and three 32-byte blocks. The port-generated default and a version with independent Backward/slow and Forward/fast/Once Only settings opened and saved byte-identically in native Sketchpad. Clicking the port default moved all three points; `action_animation_three_points_port_clicked_by_wine.gsp` preserves their changed parameters. The port imports, edits, copies, and runs the three-target button.

Native Sketchpad also created `action_animation_mixed_points_native.gsp` for a point on a segment, a point on a circle, and a free point. Its defaults are Bidirectional, Forward, and Forward respectively. The port-generated mixed button uses the selected target order and the same defaults. It opened and saved byte-identically in native Sketchpad; clicking it moved all three points, as recorded in `action_animation_mixed_points_port_clicked_by_wine.gsp`. Both native and port files import without partial view and round-trip exactly.

Indirect animation of higher constructions and exact native timing remain open. The parser preserves the other settings bytes and treats unrecognized layouts as unsupported source content.

## Ray and line points

Sketchpad 5 accepts a selected point on a ray or line in Edit > Action Buttons > Animation. The saved native files `action_animation_ray_original.gsp` and `action_animation_line_original.gsp` each contain a one-target button with Bidirectional direction and speed 24. Both import without partial view and round-trip byte-identically. The port now offers the same default and runs these buttons through the straight-path animation engine. `tests/replay_animation_button_straight_points.txt` creates port-generated buttons from the native point fixtures. Sketchpad 5 opened and saved both generated files byte-identically. Clicking the generated ray button moved its point from parameter 0.3 to 0.08548138055767585 in `action_animation_ray_port_clicked_by_wine.gsp`, which also imports and round-trips byte-identically.

## Parameter buttons

Sketchpad 5 created `action_animation_parameter_native.gsp` from a selected default parameter. Its button has one target, an anchor at (10, 47), and a 36-byte settings payload. Unlike point settings, the parameter block stores a speed of 4.0, a rate of 1.0 unit per second, and the default domain −100 to 100 scaled by 256. The default direction is Bidirectional. `assets/action_animation_parameter_group.bin` preserves this native group.

`tests/replay_animation_parameter.txt` created `action_animation_parameter_port.gsp` with the same settings and an English `Animate Parameter` label. Sketchpad 5 opened and saved it byte-identically. Clicking the button there changed the parameter, and `action_animation_parameter_port_clicked_by_wine.gsp` imports without partial view and round-trips exactly. The port runs the button without the floating Motion Controller. A port-generated button targeting both a parameter and a free point failed to open in native Sketchpad although its base document opened; multi-target parameter buttons are therefore refused until their native layout is known.

Native Properties edits produced `action_animation_parameter_native_rate2.gsp` and `action_animation_parameter_native_discrete.gsp`. The latter sets rate 2, discrete step 0.5, and domain −3 to 7. The settings block adds flag `0x08` for discrete mode. Its four numeric fields use a native encoding: a nonzero value `x` is stored as an IEEE float containing `x × 2^(floor(log₂|x|)+2)`. Thus rate 2 stores as 16, step 0.5 as 1, and the bounds −3 and 7 as −24 and 112. The parser decodes these values and preserves native files, including the long fractional parameter digits produced while animation ran.

`tests/replay_animation_parameter_custom.txt` creates a matching port button. Its 36-byte settings payload matches the native discrete button exactly; Sketchpad 5 opened and saved the file byte-identically and showed rate 2.0, step 0.5, and domain −3.0 to 7.0 in Properties. Clicking the port button moved the displayed parameter from 1.00 to 3.00 during the two-second probe; `action_animation_parameter_custom_port_clicked_by_wine.gsp` imports with a full view. The port interprets discrete rate as steps per second and continuous rate as units per second. Multi-target parameter buttons and precise timing across all modes remain open.

## Segment and circle sources

Selecting a segment or circle and choosing Edit > Action Buttons > Animation creates a two-target native button for its defining points. The target order is second point, then first point; native labels are Animate Segment and Animate Circle. `action_animation_indirect_segment_native.gsp`, `action_animation_indirect_circle_native.gsp`, and `action_animation_indirect_segment_hidden_native.gsp` capture these cases. Hidden segment endpoints remain hidden and are still targets. All import without partial view and round-trip exactly.

`tests/replay_animation_indirect.txt` creates matching English buttons from selected segment and circle sources. All three generated files, including the hidden-endpoint segment, opened and saved byte-identically in Sketchpad 5. Clicking the generated segment button moved both endpoints in `action_animation_indirect_segment_port_clicked_by_wine.gsp`, which imports and round-trips. The port's selection resolver now creates the same targets in the Animation dialog and runs them without opening the floating Motion Controller. The native circle label has odd UTF-8 byte length and the English `Animate Circle` label has even length; the writer now rebuilds the known zero terminator bytes when that parity changes.

The same native target rule holds for selected lines, rays, and polygon interiors. `action_animation_indirect_line_native.gsp` and `action_animation_indirect_ray_native.gsp` target `[2, 1]`; triangles through heptagons target their vertices in reverse order. The native heptagon label is the generic `动画多边形` (Animate Polygon), while three- through six-vertex labels name the shape. The replay creates English buttons for all seven indirect cases, and each generated file opened and saved byte-identically in Sketchpad 5. Clicking the generated quadrilateral and hexagon buttons there moved all their vertices; both clicked files import with a full view and round-trip exactly. The four- and six-source buttons also run in the Rust editor. Further source shapes and polygon sizes remain open.

## Multi-page insertion

Native Sketchpad 5 created `two_page_animation_point_native.gsp` for a constrained point on page 2 and `two_page_animation_segment_native.gsp` for its segment source. Their target records store page-local ordinals `[4]` and `[2, 1]`, corresponding to global IDs `[5]` and `[3, 2]`. The port's multi-page writer now maps target IDs to local ordinals and writes one settings block per target. `tests/replay_multi_page_animation.txt` generates matching English buttons and a file with one button on each page; all three opened and saved byte-identically in Sketchpad 5. Clicking the generated page-2 segment button there moved both endpoints, left the page-1 point unchanged, and produced `two_page_animation_segment_port_clicked_by_wine.gsp`. The Rust editor also creates and runs this page-2 button.
