# Polar circle and rectangular segment translation

Native probes used `dev/wine_roundtrip.sh` on bases generated by `tests/transform_circle_base_replay.txt` and `tests/transform_segment_base_replay.txt`. Selecting the circumference of a circle and translating it by 1 cm at 90° created one new code-21 object referencing the original circle, with header subtype 28 and the existing 60-byte polar translation payload. The native file is `tests/fixtures/polar_circle_translation_original.gsp`. The translated circle keeps the source radius and offsets its center.

Selecting a segment and translating it by fixed rectangular distances of 1 cm horizontally and 1 cm vertically created one code-17 object referencing the original segment. Its header subtype is 14, and its 52-byte constraint payload has the same fixed rectangular fields as a translated point. The native file is `tests/fixtures/rectangular_segment_translation_original.gsp`. The translated segment offsets both live source endpoints.

The importer distinguishes transformed points, segments, and circles by object code, header subtype, and source kind. The writer emits the matching segment or circle header and shares the established translation payload encoders. Both native fixtures import fully and round-trip byte-identically. `tests/transform_circle_polar_replay.txt` and `tests/transform_segment_rectangular_replay.txt` create the corresponding Rust objects, move their source points, and save. Sketchpad 5 opened and saved both generated files byte-identically after those edits.
