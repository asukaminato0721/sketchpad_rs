# Multi-page in-place edits

The native fixture `tests/fixtures/two_page_two_points_native.gsp` has one free point on each page. Dragging the page 2 point in Sketchpad 5 from screen `(280,200)` to `(320,240)` produced `two_page_point_dragged_native.gsp`, moving its raw coordinates from `(221,131)` to `(261,171)`. The native file changed the point's `0x0899` payload and cleared three opaque bytes in a page `0x0386` record.

`tests/replay_multi_page_point_move.txt` generated the same moved point through Rust. Its output differs from the native dragged file only at those three opaque bytes. Native Sketchpad displayed the point in its new position and saved the Rust file byte-identically. The same replay moves a page 1 point and inserts a Page Link before page 2; that combined file also opened and saved byte-identically in native Sketchpad.

Native two-page segment, circle, and three-point arc fixtures each contain a point constrained to the page 2 path. Dragging each in Sketchpad 5 changed its `0x07d3` constraint payload. The Rust replay in `tests/replay_multi_page_constrained_move.txt` patches that payload in place. The segment result matches the native dragged file byte for byte. The circle result has the same constraint payload as native but differs in three opaque `0x0386` bytes. The arc result differs slightly in its parameter (about 0.00006) as well as opaque header bytes. All three Rust files opened and saved byte-identically in native Sketchpad.

The multi-page writer patches existing free-point coordinates, segment/circle/arc point constraints, visibility, and Hide/Show action state in place while preserving unsupported records. It validates the reparsed objects before replacing the file. Other geometric changes remain guarded.

## Adding blank pages

The global `0x0384` record has a 16-bit page count at payload offset 2, an active page index at offset 16, and a 32-bit page count plus one at offset 24. Each page has a 216-byte `0x0386` record whose 16-bit values at payload offsets 6 and 8 are `2 * page_count - 1`. A new page can be appended by copying the second page's metadata, preamble, style records, and trailer from `two_page_blank_native.gsp` before the document's final `0x0385` record, then updating these fields. The copied block lives in `assets/blank_page_records.bin`; a unit test checks it against the native fixture. A synthetic three-page document made this way displayed page 3 in native Sketchpad and saved byte-identically.

`Document::add_blank_page` validates the expanded file before changing the editor, includes page state in Undo/Redo snapshots, and routes subsequent object edits through the existing multi-page writer. The loader now uses a valid active-page index from the header when reopening. File > Document Options exposes Add Blank Page. `tests/replay_add_pages.txt` generates a three-page sketch with one point on each page, a native two-page fixture extended with a third-page point, and a reopened three-page sketch extended to four pages. All three opened and saved byte-identically in native Sketchpad.

## Page titles

Sketchpad stores a custom page title in a `0x044c` record between that page's `0x03e8` preamble and `0x03e9` trailer. The payload contains the text, a NUL terminator, and an extra NUL when needed to make the payload length even. A generated record with payload length 7 was refused by native Sketchpad; the same text with payload length 8 opened and resaved byte-identically. Native title fixtures include `two_page_review_native.gsp` and `three_page_alpha_native.gsp`.

The loader exposes page names, the writer replaces or inserts their records, and Document Options can rename any page. Clearing a name restores the default page number. `tests/replay_page_names.txt` generated named one- and two-page files and renamed both pages of an existing native document; all three opened and resaved byte-identically in native Sketchpad. A generated three-page rename matched the minimal native-compatible record insertion byte for byte. Undo and Redo preserve page names.

## Removing pages

Native Document Options removes the selected page after confirmation. A page's record block starts at its 216-byte `0x0386` metadata record and ends before the next page's metadata or the document's final `0x0385`. Removing the block and updating the global page count, active index, count-plus-one field, and remaining page metadata produced a one-page file that opened and resaved byte-identically in native Sketchpad.

`Document::remove_page` first encodes unsaved edits, removes the selected block, reparses surviving objects, and records the prior source bytes in the Undo snapshot. It shifts Page Link destinations beyond the removed page. Native Sketchpad also permits deleting a page targeted by a surviving Page Link after an extra confirmation; it keeps the button visible but writes invalid target `0xbd66`. The port now does the same and identifies the link as unavailable on activation. The native two- and three-page examples are `one_page_removed_targeted_link_native.gsp` and `two_page_removed_targeted_link_native.gsp`; the latter leaves the old page 3 as page 2, but the link does not retarget to it. One native save gave the broken link label a nonzero padding byte, which the parser preserves. Pictures and documents with custom tool records after the pages are still guarded. `tests/replay_remove_pages.txt` covers removal of the first, middle, and last page, shifted Page Links, and links to removed pages. The generated files opened and resaved byte-identically in native Sketchpad; the middle-page result visibly retained the last page's title and point. Double-clicking a shifted valid Page Link in native Sketchpad opened page 2. Its displayed button label remains the original custom text.

## Reordering pages

The page record blocks can be moved without rewriting their page-local construction references. A synthetic three-page point file with reordered blocks and an updated active-page index opened and resaved byte-identically in native Sketchpad. `Document::move_page` encodes pending edits, reorders those blocks, maps Page Link destination indices to their new positions, and validates every reparsed object against its remapped ID. The structural Undo snapshot retains the original source bytes.

`tests/replay_move_pages.txt` moves the first or last point page, swaps two named pages, moves a page containing a segment and its parents, and moves a Page Link destination. All five files opened and resaved byte-identically in native Sketchpad. The moved segment remained visible, and double-clicking the remapped Page Link opened page 1. The button's displayed label remains its original text. Pictures and custom tool records after the pages remain guarded.

## Copying pages

Native Document Options > Add Page > From Page lists the current pages and appends a copy of the chosen page. Copies of page 1, page 2 with a segment, and a named page preserved their content and page name. A native copy of a page with a Page Link kept the original destination index. `Document::copy_page` appends the selected page block, updates the document header, validates the original and copied objects, and keeps a structural Undo snapshot. `tests/replay_copy_pages.txt` generates corresponding Rust files; all three opened and saved byte-identically in native Sketchpad 5. Documents containing picture resources or trailing custom tool page references remain guarded.

`tests/replay_multi_page_style.txt` changes a free point on page 1 and a constrained point and segment on page 2. The resulting `two_page_styled_port.gsp` differs from its native base only in three object style headers. Native Sketchpad displayed the blue thick point, purple small point, and green dashed thick segment, then saved the Rust file byte-identically. The in-place writer now patches existing visual styles on multi-page pages and checks the object header type before writing.

`tests/replay_multi_page_trace.txt` enables tracing on the page 2 segment and constrained point. Only the trace flag byte in each object header changes. The generated file opened and saved byte-identically in native Sketchpad, and toggling both flags off restores the original file byte for byte.

The multi-page writer can now insert free points on either page and points constrained to existing segments, circles, or arcs on the same page. It writes each point group before the page trailer, increments that page's object count, and converts its host ID to the page-local reference stored in the file. `tests/replay_multi_page_add_point.txt`, `tests/replay_multi_page_add_point_first.txt`, and `tests/replay_multi_page_add_constrained.txt` generated files that opened and saved byte-identically in native Sketchpad. `tests/replay_multi_page_add_mixed.txt` adds a point before page 2, a constrained point on page 2, and a Page Link in one save; its references reparse correctly and it also cross-opened byte-identically. Native Sketchpad's own new-point save rewrites additional opaque page records, so the Rust file does not match that native save byte for byte.

`tests/replay_multi_page_construct_paths.txt` creates points and a segment or circle on page 2. Each generated segment/circle object group matches the corresponding native-created group byte for byte; both full Rust files opened and saved byte-identically in native Sketchpad. `tests/replay_multi_page_construct_mixed.txt` creates a segment on page 1, then a segment and circle on page 2 with constrained points on the newly created paths and a Page Link. It reparses with the intended page-local references and also opened and saved byte-identically in native Sketchpad. The toolbar Segment and Circle tools and their Construct menu commands now use this writer on supported multi-page pages.

`tests/replay_multi_page_construct_line_ray.txt` creates page 2 lines and rays; their generated object groups match native menu constructions byte for byte, and the full files opened and saved byte-identically in native Sketchpad. `tests/replay_multi_page_midpoint_circle_segment.txt` does the same for a midpoint of an existing segment and a circle with an existing segment as its radius. `tests/replay_multi_page_midpoint_circle_segment_mixed.txt` verifies both constructions when their segment host was created earlier in the same unsaved edit. ## Selected page when reopening

Ordinary saves now update the u16 initial-page index at payload offset 16 of the global `0384` record. This is applied after content encoding for all save paths, including view-only page changes with `dirty=false`, edits on existing pages, added pages, and save after page undo/redo. The selected index and page count are validated before writing. Other header bytes and page-local object references remain intact.

A native-verified copy with index 1 opens on the second page and shows its 1.323 cm measurement; index 0 opens on the first page and shows its zero-decimal measurement. `tests/replay_page_selection.txt` generates both selected views and an added third page after undo/redo. Native Sketchpad displays the intended page and saves the generated files byte-identically. The native selected-page fixture is `two_page_selection_native_verified.gsp`.

Regression tests cover unchanged native byte preservation, navigation without a content edit, explicit save/reopen, invalid indices, content edits on both pages, added-page undo/redo, and navigation through Page Link buttons. Earlier construction/action tests retain their complete byte comparison, with only the expected native initial-page field updated to the selected view.
