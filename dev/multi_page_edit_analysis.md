# Multi-page in-place edits

The native fixture `tests/fixtures/two_page_two_points_native.gsp` has one free point on each page. Dragging the page 2 point in Sketchpad 5 from screen `(280,200)` to `(320,240)` produced `two_page_point_dragged_native.gsp`, moving its raw coordinates from `(221,131)` to `(261,171)`. The native file changed the point's `0x0899` payload and cleared three opaque bytes in a page `0x0386` record.

`tests/replay_multi_page_point_move.txt` generated the same moved point through Rust. Its output differs from the native dragged file only at those three opaque bytes. Native Sketchpad displayed the point in its new position and saved the Rust file byte-identically. The same replay moves a page 1 point and inserts a Page Link before page 2; that combined file also opened and saved byte-identically in native Sketchpad.

Native two-page segment, circle, and three-point arc fixtures each contain a point constrained to the page 2 path. Dragging each in Sketchpad 5 changed its `0x07d3` constraint payload. The Rust replay in `tests/replay_multi_page_constrained_move.txt` patches that payload in place. The segment result matches the native dragged file byte for byte. The circle result has the same constraint payload as native but differs in three opaque `0x0386` bytes. The arc result differs slightly in its parameter (about 0.00006) as well as opaque header bytes. All three Rust files opened and saved byte-identically in native Sketchpad.

The multi-page writer patches existing free-point coordinates, segment/circle/arc point constraints, visibility, and Hide/Show action state in place while preserving unsupported records. It validates the reparsed objects before replacing the file. Other geometric changes remain guarded.

`tests/replay_multi_page_style.txt` changes a free point on page 1 and a constrained point and segment on page 2. The resulting `two_page_styled_port.gsp` differs from its native base only in three object style headers. Native Sketchpad displayed the blue thick point, purple small point, and green dashed thick segment, then saved the Rust file byte-identically. The in-place writer now patches existing visual styles on multi-page pages and checks the object header type before writing.

`tests/replay_multi_page_trace.txt` enables tracing on the page 2 segment and constrained point. Only the trace flag byte in each object header changes. The generated file opened and saved byte-identically in native Sketchpad, and toggling both flags off restores the original file byte for byte.

The multi-page writer can now insert free points on either page and points constrained to existing segments, circles, or arcs on the same page. It writes each point group before the page trailer, increments that page's object count, and converts its host ID to the page-local reference stored in the file. `tests/replay_multi_page_add_point.txt`, `tests/replay_multi_page_add_point_first.txt`, and `tests/replay_multi_page_add_constrained.txt` generated files that opened and saved byte-identically in native Sketchpad. `tests/replay_multi_page_add_mixed.txt` adds a point before page 2, a constrained point on page 2, and a Page Link in one save; its references reparse correctly and it also cross-opened byte-identically. Native Sketchpad's own new-point save rewrites additional opaque page records, so the Rust file does not match that native save byte for byte.

`tests/replay_multi_page_construct_paths.txt` creates points and a segment or circle on page 2. Each generated segment/circle object group matches the corresponding native-created group byte for byte; both full Rust files opened and saved byte-identically in native Sketchpad. `tests/replay_multi_page_construct_mixed.txt` creates a segment on page 1, then a segment and circle on page 2 with constrained points on the newly created paths and a Page Link. It reparses with the intended page-local references and also opened and saved byte-identically in native Sketchpad. The toolbar Segment and Circle tools and their Construct menu commands now use this writer on supported multi-page pages.

`tests/replay_multi_page_construct_line_ray.txt` creates page 2 lines and rays; their generated object groups match native menu constructions byte for byte, and the full files opened and saved byte-identically in native Sketchpad. `tests/replay_multi_page_midpoint_circle_segment.txt` does the same for a midpoint of an existing segment and a circle with an existing segment as its radius. `tests/replay_multi_page_midpoint_circle_segment_mixed.txt` verifies both constructions when their segment host was created earlier in the same unsaved edit. The Construct menu now enables Line, Ray, Midpoint, and Circle by Center and Radius Segment on supported multi-page pages.

`tests/replay_multi_page_derived_intersections.txt` creates parallel and perpendicular lines through a point, a straight-path intersection, both line-circle intersections, and both circle-circle intersections on page 2. All four generated files passed `gsp_probe verify` and opened and saved byte-identically in native Sketchpad. The generated parallel, perpendicular, and straight-intersection object groups also match groups created through native Construct commands byte for byte. The writer checks parent types and page-local references, and rejects intersection roots without finite coordinates.
