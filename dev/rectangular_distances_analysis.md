# Rectangular translation by two marked distances

The source sketch is generated by `tests/transform_rectangular_distances_replay.txt`. It contains five free points and two point-distance measurements. Selecting measurements 6 and 7 in that order, then choosing Transform > Mark Distance makes the native Translate dialog use measurement 6 horizontally and measurement 7 vertically. The native mark-only save is byte-identical to the source file.

The native translated point is object code 20. Its `0x07d2` record contains three references: source point 5, horizontal distance 6, vertical distance 7. It has no `0x07d3` constraint payload. Its 28-byte point header uses the same transformed-point marker bytes as code 24. The imported point is at `(200, 160)` from source `(100, 210)`, horizontal distance 100 pixels, and vertical distance 50 pixels. The vertical sign follows the document's screen coordinates, where upward is decreasing y.

The native save recalculates both measurement presentation records. In each `0x0903` payload, byte 23 changes from `0x00` to `0x01` along with previously recognized presentation bytes 22 and 30. The importer now accepts that byte as a presentation variation, while retaining checks on the remaining record bytes and measurement style. The complete native file is saved as `tests/fixtures/rectangular_marked_translation_original.gsp` and imports without partial view.

`tests/transform_rectangular_marked_replay.txt` creates the same reference structure, moves one defining point for each measurement, and saves the result. Sketchpad 5 opened and saved that generated file byte-identically after the moves. Core and editor tests verify both marking order and the translated point's dependency on the two measurements.
